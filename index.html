AHomework A.I · similarity metric

Cosine, dot, or Euclidean?

Cosine distance

1 − (a·b) / (‖a‖‖b‖)

Compares direction only. Long and short passages compete fairly. 0 = same direction.

Dot product (“ip”)

1 − a·b

Direction and length. Fastest. Longer vectors score higher if they aren't normalized.

Euclidean (“l2”)

‖a − b‖²   (Chroma: squared)

Straight-line gap. Sensitive to vector length. Chroma reports the squared value.

MiniLM outputs vectors of length 1. For unit vectors, ‖a−b‖² = 2 − 2·cos and a·b = cos, so all three give the same ranking. The TA run built all three stores: the top-5 IDs matched for all 5 queries. Only the printed numbers change. Flip “Show distance as” on the previous slide to see it.

Quick check: your store uses cosine. You switch to l2 and rebuild. What changes?

CPart C · who grades the grader?

Three judges, same prompt

Watch them answer the same 1-passage prompt

Asked to score one document, Gemma 270M returns scores for five documents it made up, three times in a row. The code then rejects the reply (“Expected 1 document scores, got 5”). That's the “judge failed” you see in Colab. A failed judgment is missing data, not a score of 1.

CHomework C.II · the metrics table

What the TA run reported

Precision@k = relevant ÷ unique results in the top k. Recall@k = relevant found ÷ all relevant chunks in the pool. The starter's evaluate_precision_recall has no pool, so with one document per question its “recall” is just 0 or 1. Say so in your report.
